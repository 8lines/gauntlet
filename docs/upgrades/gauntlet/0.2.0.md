# Upgrade `gauntlet` from 0.1.9 to 0.2.0

What changed in `gauntlet` 0.2.0 and what an operator must or may change when upgrading from 0.1.9.
Apply every guide between the deployed version and the target, oldest first, as described in
[upgrade guides](../README.md).

## Changes

- Added: Gauntlet can require a shared or per-user password and static API tokens for the dashboard, widget, REST API and MCP endpoint.

## Steps

### Authentication (optional)

Authentication stays off unless the configuration turns it on: without an
`auth` section in the v1 configuration, or with `auth.mode: none`, Gauntlet
behaves as 0.1.9 and logs a `GAUNTLET_AUTH_DISABLED` warning at startup. No
step is needed to keep that behaviour.

To require a password:

1. Generate the signing secret with the 0.2.0 image
   (`node dist/auth-cli.js generate-secret`) and set it as
   `GAUNTLET_AUTH_SECRET`, hex or base64url, at least 32 bytes. It is a secret:
   keep it in the private operator store, never in `config.yaml`.
2. Hash the password (`node dist/auth-cli.js hash-password`) and add the
   `auth` section to the configuration with `mode: password`, `publicUrl` (the
   exact origin people open Gauntlet at) and `password.shared` or
   `password.users`. API tokens are added under `auth.tokens`
   (`node dist/auth-cli.js create-token`).

Compose: the 0.2.0 distribution passes `GAUNTLET_AUTH_SECRET` from the
installed `.env` to the container. A distribution directory from 0.1.9 does
not, so replace the distribution files (the `gauntlet` wrapper,
`compose.yaml` and the schema) with the 0.2.0 release archive while keeping
the installed `.env` and `config.yaml`, then add `GAUNTLET_AUTH_SECRET=` to
`.env`. See [Compose authentication](../../../deploy/compose/README.md#authentication).

Helm: the 0.2.0 chart has no values for authentication; keep authentication
off on Kubernetes.

See [authentication](../../deployment/authentication.md) for the complete
configuration.

## Verify

Follow the verification in the [upgrade runbook](../../releases/upgrading.md#verify).
With authentication on, also check that the dashboard asks for the password and
that a request without a session or token gets `401`.
