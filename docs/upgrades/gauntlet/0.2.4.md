# Upgrade `gauntlet` from 0.2.3 to 0.2.4

What changed in `gauntlet` 0.2.4 and what an operator must or may change when upgrading from 0.2.3.
Apply every guide between the deployed version and the target, oldest first, as described in
[upgrade guides](../README.md).

## Changes

- Added: Gauntlet can be served below a URL path prefix such as `/tester` on a host shared with other applications, set with `basePath` in the configuration or `GAUNTLET_BASE_PATH`, with the dashboard, API, widget, MCP endpoint and session cookie all below the prefix and `/health` and `/ready` still at the root.
- Added: The Helm chart can take the authentication signing secret from an existing Secret with `auth.existingSecret`, accepts `config.auth` for password sign-in, and adds container environment variables with `extraEnv` and `envFrom`.

## Steps

### Base path (optional)

Nothing changes unless you set a base path: the default `basePath: ""` serves
Gauntlet at the root as before, and the dashboard and widget files are served
unchanged.

To serve Gauntlet below a prefix, for example `https://qa.example/tester`:

- Route the prefix to Gauntlet without stripping it; Gauntlet expects requests
  to arrive as `/tester/...`.
- Source, Compose or a custom container: set `basePath: /tester` at the top of
  the configuration file, or set `GAUNTLET_BASE_PATH=/tester` in the
  environment. A non-empty `GAUNTLET_BASE_PATH` overrides `basePath`; unset or
  empty uses the configuration. The value starts with `/`, has no trailing
  slash, query, fragment, `%`-escape or dot segment; an invalid value fails
  startup.
- Helm: set the new top-level value `basePath: /tester` (default `""`), which
  the chart passes as `GAUNTLET_BASE_PATH`, and an Ingress path `/tester` with
  `pathType: Prefix`. The probes keep calling `/ready` and `/health` at the
  root, which stay available.

With a base path, the dashboard opens at `/tester/`, `/tester` redirects there,
the API is `/tester/api/v1`, MCP clients connect to `/tester/mcp`, and pages
embedding the widget include `https://qa.example/tester/widget/loader.js`.
Every other path outside the prefix answers `404`. In password mode keep
`auth.publicUrl` an origin (`https://qa.example`); testers sign in again once,
because the session cookie is now sent with `Path=/tester`.

### Helm extra environment (optional)

Helm only. The new top-level values default to the previous behaviour, so an
existing values file keeps working unchanged:

- `auth.existingSecret` (default `""`): the name of a Secret in the release
  namespace with the key `GAUNTLET_AUTH_SECRET`, generated with
  `node dist/auth-cli.js generate-secret`. The chart reads it with
  `secretKeyRef` and never renders it. Together with `config.auth` (the same
  object as `auth` in the configuration file, for example `mode: password`,
  `publicUrl` and `password.shared.hash`) it enables password sign-in through
  Helm. A render with `config.auth.mode: password` fails when no
  `auth.existingSecret`, `extraEnv` entry named `GAUNTLET_AUTH_SECRET` or
  `envFrom` source can supply the secret.
- `extraEnv` (default `[]`): extra container environment variables, each with
  a `name` and either a literal `value` or a `valueFrom` reference. Names must
  be unique; the variables the chart sets itself, such as `GAUNTLET_HOST` and
  `GAUNTLET_BASE_PATH`, are rejected.
- `envFrom` (default `[]`): Secrets (`secretRef`) or ConfigMaps
  (`configMapRef`) whose keys become environment variables, with an optional
  `prefix`. The chart's own variables take precedence over them.

Create the Secret with the platform's approved secret manager before the
upgrade, for example a Secret named `gauntlet-auth`, and set
`auth.existingSecret: gauntlet-auth`.
