# Gauntlet AI Skills Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship two installable, pressure-tested AI skills that safely integrate Gauntlet into non-production applications and author narrow application-owned extensions without enabling production use or generic remote execution.

**Architecture:** Repository-owned skills live under `skills/`, while synthetic pressure prompts, scorecards, raw outcomes, and content-bound verification receipts live separately under `skill-evals/`. Each skill follows its own RED–GREEN–REFACTOR cycle: fresh agents first face the scenarios without the skill, the minimal skill addresses observed failures, and the same plus forward scenarios are rerun with the skill. A local installer copies only validated skill directories into a selected agent-skills directory and never mutates an application by itself.

**Tech Stack:** Codex agent skills (`SKILL.md`, `agents/openai.yaml`, progressive-disclosure references), Node.js 24 `node:test`, JSON Schema, multi-agent pressure tests, Gauntlet conformance tooling

## Spec

Implement the approved design in `docs/superpowers/specs/2026-09-02-release-standalone-safety-skills-design.md`. The skill-writing RED–GREEN–REFACTOR discipline below is part of the deliverable, not optional evaluation commentary.

## Global Constraints

- **REQUIRED BACKGROUND:** Before executing any skill-authoring task, read `superpowers:test-driven-development`, `skill-creator`, and `superpowers:writing-skills`, including `testing-skills-with-subagents.md`.
- Apply the skill TDD iron law independently to each skill: no `SKILL.md`, reference, or `agents/openai.yaml` may be authored before that skill's failing no-guidance baseline has been run and recorded.
- Complete, validate, forward-test, install-test, and commit `gauntlet-app-integration` before starting any baseline or authoring work for `gauntlet-extension-authoring`.
- Baseline and guided samples use fresh isolated agent contexts. Baseline workspaces must not contain either target skill or leak its intended answer.
- Discipline scenarios combine at least three pressures from time, authority, sunk cost, economic consequence, exhaustion, and social pressure.
- Behavior-shaping wording uses a no-guidance control and at least five independent samples per wording variant. A human/independent reviewer reads every sample; regex or keyword counts are not a behavioral verdict.
- If a control does not exhibit a proposed failure, do not add rationalization-specific prose for that failure. Retain only safety requirements mandated by the product specification and positive instructions needed for valid work.
- Skills are automatically discoverable; do not set `allow_implicit_invocation: false`.
- Skill names contain lowercase letters and hyphens only. YAML descriptions start with the literal prefix `Use when`, describe triggering conditions only, use third person, and do not summarize the workflow.
- `SKILL.md` stays below 500 words when possible. Heavy framework procedures and examples belong in linked `references/` files; add no unused asset, script, or README inside a skill.
- Product safety remains defense in depth. A skill can require evidence and refuse unsafe work, but it must never claim that environment metadata alone proves physical infrastructure identity.
- Both adapters and the control plane remain unavailable for missing, unsupported, production-like, or mismatched environments. There is no production override or break-glass path.
- Both the dashboard and adapter routes remain private because Gauntlet authentication is deferred in v0.1.
- Integration uses released `0.1.0` packages/artifacts, never copied monorepo source, path packages, `latest`, or fixture defaults.
- Integration mounts exactly one normalized `/_gauntlet/v1` transport and keeps the browser on `/api/v1`; it does not author domain operations.
- Extension authoring requires an already verified integration. It does not mount transports, edit ingress, add public routes, or change the Gauntlet deployment.
- Extension input must never select an arbitrary SQL statement, shell command, HTTP URL, route, class, command name, queue topic, filesystem path, or reflection target.
- `destructive` operations require confirmation and required idempotency. Confirmation prevents accidents and is never authentication or application-domain authorization.
- `dryRunSupported: true` requires verified propagation to application code and a mutation-sentinel test. Otherwise declare `false` or create a separate read-only preview operation.
- Skill evaluations use synthetic repositories and values only. They never receive production credentials, customer data, live kubeconfig, cloud credentials, or deployed secrets.

- [ ] **Step 1: Write failing validation tests with synthetic skills**

Create `scripts/skills/test/support.mjs` with concrete, synthetic-only fixtures:

```javascript
import { access, mkdir, mkdtemp, writeFile } from "node:fs/promises";
import { tmpdir } from "node:os";
import { dirname, join } from "node:path";
import { hashSkill } from "../validate.mjs";

export async function exists(path) {
  try {
    await access(path);
    return true;
  } catch (error) {
    if (error.code === "ENOENT") return false;
    throw error;
  }
}

export async function fixtureSkill({ name, skill, references, openai }) {
  const root = await mkdtemp(join(tmpdir(), "gauntlet-skill-"));
  const skillRoot = join(root, "skills", name);
  await mkdir(join(skillRoot, "agents"), { recursive: true });
  await writeFile(join(skillRoot, "SKILL.md"), skill, "utf8");
  await writeFile(join(skillRoot, "agents", "openai.yaml"), openai, "utf8");
  for (const [relativePath, contents] of Object.entries(references)) {
    const destination = join(skillRoot, "references", relativePath);
    await mkdir(dirname(destination), { recursive: true });
    await writeFile(destination, contents, "utf8");
  }
  return root;
}

export async function writeReceipt(root, name, skillSha256) {
  const evaluationRoot = join(root, "skill-evals", name);
  const resultsRoot = join(evaluationRoot, "results");
  await mkdir(resultsRoot, { recursive: true });
  for (const phase of ["baseline", "guided", "forward"]) {
    await writeFile(
      join(resultsRoot, `${phase}.jsonl`),
      `${JSON.stringify({ phase, synthetic: true })}\n`,
      "utf8",
    );
  }
  const result = (scenario, samples, verdict) => ({
    scenario,
    samples,
    reviewedSamples: samples,
    verdict,
  });
  const receipt = {
    schemaVersion: 1,
    skill: name,
    skillSha256,
    evaluatedAt: "2026-09-03T12:00:00.000Z",
    baseline: {
      transcript: "results/baseline.jsonl",
      scenarioResults: [result("no-guidance-control", 5, "expected-failure-observed")],
    },
    guided: {
      transcript: "results/guided.jsonl",
      scenarioResults: [result("guided-micro-scenario", 5, "pass")],
    },
    forward: {
      transcript: "results/forward.jsonl",
      scenarioResults: [result("forward-scenario", 1, "pass")],
    },
    verdict: "pass",
  };
  await writeFile(
    join(evaluationRoot, "verification.json"),
    `${JSON.stringify(receipt, null, 2)}\n`,
    "utf8",
  );
}

export async function validFixture() {
  const root = await fixtureSkill({
    name: "safe-integration",
    skill: "---\nname: safe-integration\ndescription: Use when integrating a safe fixture.\n---\n\nRead [safety](references/safety.md).\n",
    references: { "safety.md": "# Safety\n\nUse synthetic non-production data.\n" },
    openai: "interface:\n  display_name: \"Safe Integration\"\n  short_description: \"Connect a safe fixture application\"\n  default_prompt: \"Use $safe-integration to connect this fixture.\"\n",
  });
  await writeReceipt(root, "safe-integration", await hashSkill(join(root, "skills", "safe-integration")));
  return root;
}

export async function occupiedDestination(name) {
  const destination = await mkdtemp(join(tmpdir(), "gauntlet-skills-"));
  await mkdir(join(destination, name), { recursive: true });
  await writeFile(join(destination, name, "SKILL.md"), "occupied\n", "utf8");
  return destination;
}
```

- [ ] **Step 3: Define the evaluation receipt schema**

Use this closed shape:

```json
{
  "$schema": "https://json-schema.org/draft/2020-12/schema",
  "type": "object",
  "required": ["schemaVersion", "skill", "skillSha256", "evaluatedAt", "baseline", "guided", "forward", "verdict"],
  "properties": {
    "schemaVersion": { "const": 1 },
    "skill": { "type": "string", "pattern": "^[a-z0-9]+(?:-[a-z0-9]+)*$" },
    "skillSha256": { "type": "string", "pattern": "^[a-f0-9]{64}$" },
    "evaluatedAt": { "type": "string", "format": "date-time" },
    "baseline": { "$ref": "#/$defs/phase" },
    "guided": { "$ref": "#/$defs/phase" },
    "forward": { "$ref": "#/$defs/phase" },
    "verdict": { "const": "pass" }
  },
  "$defs": {
    "phase": {
      "type": "object",
      "required": ["transcript", "scenarioResults"],
      "properties": {
        "transcript": { "type": "string", "pattern": "^results/.+\\.jsonl$" },
        "scenarioResults": {
          "type": "array",
          "minItems": 1,
          "items": {
            "type": "object",
            "required": ["scenario", "samples", "reviewedSamples", "verdict"],
            "properties": {
              "scenario": { "type": "string", "minLength": 1 },
              "samples": { "type": "integer", "minimum": 1 },
              "reviewedSamples": { "type": "integer", "minimum": 1 },
              "verdict": { "enum": ["expected-failure-observed", "pass"] }
            },
            "additionalProperties": false
          }
        }
      },
      "additionalProperties": false
    }
  },
  "additionalProperties": false
}
```

The validator additionally requires `reviewedSamples === samples`, baseline and guided micro scenarios to have at least five samples, guided/forward verdicts to be `pass`, and transcript files to exist.

- [ ] **Step 4: Implement stable skill hashing and validation**

`listSkillFiles()` returns `SKILL.md`, `agents/openai.yaml`, and every regular file beneath `references/`, sorted by relative POSIX path. `hashSkill()` hashes each path, a NUL byte, its bytes, and another NUL byte with SHA-256. It ignores evaluation output and filesystem timestamps.

`validateSkill()` verifies:

- directory and required files exist;
- frontmatter name equals directory name;
- description begins `Use when`, stays below 500 characters, and contains no workflow summary keys such as `then`, numbered steps, or `workflow`;
- every relative Markdown reference resolves inside the skill;
- `agents/openai.yaml` strings are quoted and `default_prompt` includes a literal dollar sign followed by the frontmatter name, such as `$safe-gauntlet-integration`;
- there are no scaffold markers or empty reference files;
- the evaluation receipt validates and matches `hashSkill()`.

# Integrating Gauntlet

## Core Principle

Complete an integration only when code, deployment, and negative-path evidence agree that one explicit adapter is private and non-production. Metadata alone cannot prove physical infrastructure identity.

## Required Routing

Read [safety gates](references/safety-gates.md) first. Then read exactly one stack guide: [Node](references/node.md), [Next.js](references/nextjs.md), [Symfony](references/symfony.md), or [Spring](references/spring.md). Read [deployment](references/deployment.md) when connecting Compose or Kubernetes, and always finish with [verification](references/verification.md).

Address only rationalizations actually observed in baseline, plus mandatory product invariants.

- [ ] **Step 3: Write the mandatory safety gates reference**

`safety-gates.md` requires evidence in this order:

```text
1. Identify the exact deployment and application environment from real configuration.
2. Reject missing/unsupported kind and production aliases prod, production, or live, including separated suffixes.
3. Confirm adapter disabled-by-default and no bypass flag.
4. Identify the private network control for dashboard and adapter prefix.
5. Confirm a stable secret reference without reading or printing its value.
6. Match process/pod count to RunStore, coordinator, cancellation, and event ownership.
7. Continue only when all gates pass; otherwise leave integration incomplete.
```

Include a rationalization table only for exact excuses found in `baseline-findings.md`. Red flags always include relabeling prod as staging, relying on an obscure URL, generating per-process secrets, reducing only control-plane replicas, and claiming hardened Next.js transport from decoded-route tests.

- [ ] **Step 4: Write stack-specific positive recipes**

Each reference uses released `0.1.0` coordinates and produces the same contract:

- Node: Core + Node transport, structured environment, stable secret, exactly one raw HTTP mount.
- Next.js: Next bridge plus trusted raw-request ingress and adversarial encoded/double-slash raw-target tests; App Router checks alone are insufficient.
- Symfony: PHP 8.3/Symfony 7.2-compatible bundle config, one route import, environment-scoped bundle enablement, stable secret, and truthful worker/store/coordinator binding.
- Spring: Java 21 starter, structured properties, stable secret, exactly one auto-configured transport, and truthful replica/runtime components.

Do not include application-specific domain operations in these guides.

- [ ] **Step 5: Write deployment and verification references**

`deployment.md` covers only:

```text

Kubernetes -> exact 0.1.0 OCI chart, one replica, ClusterIP, ingress disabled, no service-account token/RBAC, explicit targets, private NetworkPolicy/ingress evidence.
```

`verification.md` requires command/output evidence for disabled prefix, startup denial, environment mismatch on every proxy path, live conformance, public-ingress denial, and one-transport routing. The completion report has `Environment evidence`, `Network evidence`, `Runtime evidence`, `Tests`, and `Unresolved risk`; it may say complete only when unresolved risk is empty.
